# Вимоги до StudyFlow

## Призначення

StudyFlow допомагає одному студенту впорядковувати навчальні задачі без реєстрації та зовнішнього сервера. Система працює в терміналі й зберігає дані локально.

## Функціональні вимоги

1. Додавати задачу з назвою, дисципліною та необов'язковим терміном у форматі YYYY-MM-DD.
2. Відхиляти порожню назву та невалідну дату.
3. Показувати задачі за датою створення з ідентифікатором, дисципліною, терміном і статусом.
4. Фільтрувати список за дисципліною та статусом.
5. Позначати відкриту задачу завершеною за її ідентифікатором.
6. Показувати кількість відкритих і завершених задач та кількість прострочених відкритих задач.
7. Експортувати всі задачі в CSV із заголовками.
8. Повертати зрозумілі повідомлення та ненульовий код виходу при помилці вводу.

## Нефункціональні вимоги

- Локальні дані: SQLite, без мережевих запитів застосунку.
- Відтворюваність: однаковий результат для однакових даних і дати перевірки.
- Перевірюваність: автоматичні тести для валідації, статусу, фільтрів, зведення та експорту.
- Безпека: параметризовані SQL-запити, без виконання довільного вводу як коду.
- Продуктивність: достатня для кількох тисяч задач на звичайному ноутбуці.

## Архітектура

- `studyflow/domain.py` — валідація та сутність задачі.
- `studyflow/storage.py` — SQLite-запити.
- `studyflow/cli.py` — аргументи командного рядка й повідомлення користувачу.
- `tests/` — перевірки поведінки.

## Агентна IDE

Обрано Claude Code. Перевірено на цьому комп'ютері: команда `claude --version` працює. IDE підтримує локальні MCP-сервери, запуск команд, файл `CLAUDE.md`, hooks у `.claude/settings.json` і skills у `.claude/skills/`.

## Критерій завершення

Команди `add`, `list`, `done`, `summary`, `export` працюють із тестовою SQLite-базою; `pytest` проходить без помилок.
