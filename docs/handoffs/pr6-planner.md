# Handoff від Planner: `studyflow upcoming --days N`

**Ціль.** Додати команду `upcoming --days N`. Вона показує відкриті задачі з терміном від сьогодні до сьогодні+N днів включно. Від'ємне N відхиляється з ненульовим кодом виходу. Команда лише читає дані й нічого в базі не змінює. Файли я не редагував, нотатки vault теж.

## 2. План по файлах

**`studyflow/domain.py`**
- Додати `validate_days(days: int) -> int`.
- Якщо `days < 0`, кидати `ValueError("Кількість днів не може бути від'ємною")`.
- Причина: валідація за архітектурою належить до domain, як і `validate_task`.

**`studyflow/storage.py`** (правило W1, буде запит на підтвердження)
- Додати `upcoming(self, days: int, today: date | None = None) -> list[Task]`.
- Спершу викликати `validate_days(days)`, потім `start = today or date.today()`.
- Кінець вікна рахувати так: `end = start + timedelta(days=days)`. Якщо виникне `OverflowError`, брати `date.max`. Без цього дуже велике N (наприклад, `--days 10**9`) дало б traceback замість нормальної відповіді.
- SQL тільки з `SELECT`:
  ```sql
  SELECT id, title, course, due, status FROM tasks
  WHERE status = 'open' AND due IS NOT NULL AND due BETWEEN ? AND ?
  ORDER BY due, id
  ```
  з параметрами `(start.isoformat(), end.isoformat())`.
- Причини:
  - `BETWEEN` включає обидві межі, як і вимагає задача.
  - Порядок `due, id` стабільний, тож результат відтворюваний.
  - Ні `UPDATE`, ні `INSERT` немає, тож дані не змінюються.
  - Параметр `today` повторює підхід `summary` і дозволяє тестувати на фіксовану дату.

**`studyflow/cli.py`**
- Додати підкоманду: `up = sub.add_parser('upcoming'); up.add_argument('--days', type=int, required=True)`.
- Обробка: `for task in store.upcoming(args.days): print(...)` у тому самому форматі, що й `list`.
- Якщо задач немає: `Немає відкритих задач на найближчі N дн.` у stdout, код виходу `0`.
- Причини:
  - Від'ємне N дає `ValueError`, а наявний `except` уже перетворює його на код `2`, тож нової логіки обробки помилок не треба.
  - `argparse` приймає `--days -1` як значення, бо в парсері немає опцій, схожих на від'ємні числа.
  - Нечислове значення `argparse` відхиляє сам, теж із кодом `2`.

**`tests/test_upcoming.py`** (новий файл). Окремий файл, щоб зміну було легко відстежити.

## 4. Обмеження
- Схему БД не змінювати. Нових залежностей не додавати, тільки стандартна бібліотека.
- Тільки параметризований SQL.
- Правки в `storage.py` потребують підтвердження (W1). Коміт теж потребує підтвердження (W3). Push у `main` заборонено (B1).
- Vault оновлювати тільки через MCP.

## 5. Що вирішено як припущення
- Задачі без терміну, прострочені та завершені у вивід не потрапляють. Це випливає з формулювання «відкриті задачі з терміном від сьогодні до сьогодні+N», підтвердження від автора задачі немає.
- Сьогоднішню дату визначає системний годинник, `date.today()`. Окремого прапорця `--today` у CLI не додаємо, бо його не просили.
- Формат виводу такий самий, як у `list`.

## 6. Відкриті питання
1. `--days` обов'язковий, чи потрібне значення за замовчуванням (наприклад, 7)? У плані зараз `required=True`, бо це буквальне прочитання задачі.
2. Який текст показувати, коли задач немає? Чи це має бути порожній вивід?
3. Чи додавати фільтр `--course` за аналогією з `list`? У плані його немає, бо команда має бути мінімальною.
4. Чи записати рішення про межі вікна («обидві межі включно, прострочені не показуються») окремою нотаткою в `Decisions/` через MCP?
