# Вимоги до agent harness

## Мета

Harness дає агенту контрольований доступ до актуальних знань StudyFlow, повторювані процедури розробки й технічні обмеження дій.

## Джерела даних

| Джерело | Коли виникає | Канал доступу |
|---|---|---|
| Вимоги та ЗАВДАННЯ.md | ПР1 | Файли репозиторію застосунку |
| Код і тести | ПР3–ПР6 | Файли репозиторію застосунку |
| Git-історія | Після кожної практичної | Локальний git; GitHub MCP для GitHub-даних |
| Vault Obsidian | ПР2 | Лише `studyflow-vault` MCP |
| Правила й skills | ПР4–ПР5 | `.claude/` і `docs/` |
| Результати тестів | Після змін коду | `pytest`, журнал запуску |

## Цільові задачі

1. Реалізація обмежених CLI-функцій з тестами за вимогами: зменшує повторення та залишає перевірний результат.
2. Рев'ю змін проти архітектури й guardrails: ловить порушення до коміту.
3. Створення ADR-нотаток через MCP: зберігає мотивацію рішень окремо від коду.
4. Пошук релевантних знань перед зміною: знижує ризик забути попереднє рішення.

## Первинні guardrails

- **Allow:** читання коду, вимог, запуск локальних тестів, пошук через MCP.
- **Warn:** редагування бізнес-логіки, міграція схеми, коміт у робочу гілку.
- **Block:** видалення рішень із vault, запис секретів, прямий push у `main`, виконання руйнівних команд.

## Межа репозиторіїв

Vault фізично лежить окремо від робочої директорії Claude Code. MCP-конектор має типізовані інструменти для запису та читання. Векторний індекс ПР7 є похідним артефактом і не замінює Markdown-нотатки.
